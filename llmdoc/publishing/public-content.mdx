# Public Content Surfaces

中文检索语汇：官网英文独立网址；多语言 SEO；/en/；hreflang 与 canonical；语言切换与锚点；静态英文正文；官网嵌入预览与独立发布；Landing 和产品文档如何部署；llms.txt 如何生成；产品内容如何避免漂移。

## Independent publication boundary

The public brand website is owned by `apps/website`: tracked static source is built for the independent `geok.cloud` site and for the application’s `/official-site` preview. Publishing the embedded copy in a Web image does not publish the independent Nginx website root. Server publication and rollback policy are owned by `operations/deployment.mdx`.

`apps/landing` and `docs/` are separate public-content surfaces; they must not be mistaken for the static brand website. The landing app is a Next.js package intended for Vercel; `docs/` is a Mintlify site. The landing `/docs` route forwards to the configured external documentation URL rather than serving Mintlify content itself.

Public content describes capabilities but is not a runtime source of truth. Provider support, setup commands, environment variables, scoring rules, and deployment claims must be checked against code and runtime configuration before publication.

## URL and crawler contracts

The static website emits the public origin from its build script, with matching robots and sitemap sources; the separate landing app uses its site configuration. An embedded preview path must not become a public canonical URL. Placeholder `.example` fallbacks must never be treated as production-ready. Sitemap, robots, structured data, `llms.txt`, and `llms-full.txt` should agree on the canonical public origin and product identity.

The separate product landing retains GEOK’s explicit fork attribution while presenting its own identity. Shared UI components do not make the landing deployment part of the self-hosted application.

## Static website locale contract

Chinese is the authored HTML. English dictionaries selected by each page’s `data-page` are applied during the build, producing an English counterpart under `/en/` for every source route. The response itself contains the translated title, description, body and bound attributes; runtime text replacement or a browser language preference must not determine the language of a canonical URL. The Chinese main content stays intact.

Language selectors are ordinary links to corresponding pages. English navigation remains within English page routes, while assets and external tool links retain their own destinations. JavaScript only preserves the current fragment when switching language; direct links and language navigation work without it. Do not restore automatic language redirects based on saved browser state.

Every variant canonicalizes to itself and lists reciprocal `zh-CN`, `en` and `x-default` alternates, with Chinese as the fallback. These URLs use the public HTTPS origin even in the embedded preview. Page-level `WebPage` structured data follows the variant’s URL, language, title and description; shared organization, brand and website identifiers remain stable across languages. English pages must not canonicalize to Chinese or create separate brand identities.

The build discovers HTML pages, but the tracked sitemap is maintained separately. Adding or removing a page therefore requires updating both its translations and sitemap language entries; do not assume route discovery updates the sitemap. Missing English bindings fail the build rather than silently yielding incomplete translations.

## Build and publication constraints

Translation bindings follow a deliberately narrow HTML convention: `data-i18n` targets leaf elements, and translated attributes use the existing `data-i18n-*` markers. The build uses source transformations rather than a general HTML parser. Markup or formatter changes must retain correct translations, paired language links and canonical tags, including multiline tags. Verify these invariants against generated HTML in both deployment modes.

The independent publisher runs with Node only, no installed build dependencies and no network. Keep this build dependency-free. The embedded mode prefixes browser navigation and resource paths with `/official-site`; the standalone mode serves the same locale pairs from the root. Generated output is not the editable source. Local preview must build first, and source changes require a rebuild before refresh.

The website tests check static translations, language pair reciprocity, sitemap coverage, anchors and resources, preservation of Chinese main content, and standalone construction without installed dependencies. Consult those tests and the module README for executable checks. Publication must additionally verify the public English route and its canonical/alternate URLs; successful local rendering alone is not evidence of deployment or search-engine indexing.

## Drift risks

The generic self-host documentation describes published-image and host-Nginx deployment, while the current production server uses source-built server Dockerfiles and an external Docker edge proxy. These are intentionally different modes and must not be collapsed into one set of commands.

Environment-variable tables must be reconciled with validation code, Compose overrides, and `.env.example`. In particular, ClickHouse application queries use the `analytics` database explicitly; a configurable-looking default must not imply that changing it transparently relocates those tables.

Page layouts, blog copy, and individual navigation labels are cheap to recover from source and do not belong in llmdoc. The durable contract is ownership, deployment independence, canonical URL behavior, and synchronization with the actual product.
